# O256 後續研究方向與高成本實驗暫存（2026-07-13）

## 目的

這份文件用來記錄「目前不一定要由本研究繼續完成，但很適合留給後續學弟妹接續」的研究方向。

目前 O256 主結果已可先以 `exp52` / `exp53` 的 StageE full from-scratch formal 結果作為最終版本：seed62 與 seed61 都已在同一套 StageE protocol 下完整重頭訓練通過。`exp54` 已於 2026-07-14 實作為 seed63 最後保險驗證，由使用者自行執行；若通過，可補強跨三個 seed 的穩定性論述。接下來若再做其他實驗，應先判斷它是「低成本補強」還是「高成本新研究線」。若需要大量 seed、完整重訓、架構重寫或長期探索，原則上先記錄在此，不急著納入目前論文主線。

## 是否還需要 exp54？

原本不一定需要；但目前已決定把它作為最後收尾保險驗證。

`exp54` 的價值是補第三個 seed，例如 seed63，讓 StageE 從「兩個 seed 通過」變成「三個 seed 通過」。這會讓穩定性論述更強，但它的成本也高，因為它不是小補丁，而是一整套 full from-scratch formal rerun。

如果 `exp54` 通過，建議把它補進最終 cross-seed StageE table；如果沒有通過，也不必推翻 exp52 / exp53，而是把它作為 seed sensitivity / 後續穩定性改善方向。

## 後續方向一：更多 seed 的 StageE 穩定性驗證

| 項目 | 內容 |
|---|---|
| 可能實驗 | `exp54`: StageE full from-scratch seed63 |
| 目的 | 確認 StageE 是否在第三個 seed 也穩定通過 |
| 成本 | 高 |
| 預期時間 | 約等同 exp52 / exp53，一次完整 base + refiner |
| 需要資料 | 同一套 train / finaltest1000 split、同一 attack table |
| 成功條件 | PSNR >= 33.8、Clean BA >= 99、Avg BA >= 98、Min BA >= 90 |
| 現階段建議 | 已實作為最後保險驗證；跑完後更新最終表 |

代表意義：

如果 seed63 也通過，就可以更有把握地說 StageE protocol 不是 seed-specific tuning，而是一套跨 seed 穩定的正式 protocol。不過它主要是「加強證據」，不是現在主結論成立的必要條件。

## 後續方向二：S / strength 相關補充實驗

| 項目 | 內容 |
|---|---|
| 可能實驗 | 不同 strength / S 條件下的 PSNR-BA trade-off |
| 目的 | 看浮水印強度、畫質、robustness 之間是否有更完整的曲線 |
| 成本 | 中到高 |
| 風險 | 需要多組完整或半完整訓練，容易變成大範圍 sweep |
| 現階段建議 | 適合後續研究，不建議現在為了論文主線大規模展開 |

代表意義：

目前主線已經有可用的 StageE formal 結果。若後續想把方法變成更完整的系統，可以研究不同 S / strength 設定如何影響 PSNR、Clean BA、Avg BA、Min BA，進一步建立可調式 trade-off 規則。

## 後續方向三：bitplane 對應與弱 bit 定位

| 項目 | 內容 |
|---|---|
| 已做基礎 | `exp25`, `exp48` |
| 目前觀察 | bitplane 可以用來診斷，但弱 bit 不一定固定 |
| 可能實驗 | 追蹤單一 bit / channel 在 base、refiner、attack 後是否仍可定位 |
| 成本 | 中到高 |
| 風險 | 需要 per-bit/per-image/per-attack 大量診斷，分析成本高 |
| 現階段建議 | 很適合後續學弟妹接續，作為機制型研究 |

代表意義：

這條方向不是單純追更高分數，而是想回答「哪些 bit 比較脆弱、脆弱性是否穩定、能不能針對特定 bit 做訓練或修復」。如果做得完整，會讓 O256 從經驗型調整變成更可解釋的 bitplane-aware watermarking 方法。

可能設計：

1. 固定一個正式模型，例如 exp52 或 exp53。
2. 對每張圖、每個 attack、每個 bit 計算 bit error。
3. 分析弱 bit 是否集中在特定 channel / bitplane。
4. 追蹤 refiner 前後哪些 bit 被修好、哪些 bit 被弄壞。
5. 再設計 bit-specific loss 或 bit-specific sampling schedule。

## 後續方向四：refiner clean BA damage / evidence preservation

| 項目 | 內容 |
|---|---|
| 已做基礎 | `exp31`, `exp46`, `exp47`, `exp48`, `exp50`, `exp51` |
| 目前觀察 | refiner 可以補畫質，但若設計太粗，可能抹掉 watermark evidence |
| 可能實驗 | 找出 refiner 常破壞哪些位置、頻率區域、bit 或 image group |
| 成本 | 中到高 |
| 風險 | 可能需要改 refiner 架構，不只是改訓練參數 |
| 現階段建議 | 適合做成下一代架構型研究 |

代表意義：

目前 StageE 的思路已經不是「盲目修圖」，而是讓 refiner 在修圖時更顧 decoder / message。後續可以更進一步研究 refiner 到底在哪些影像、哪些區域、哪些頻率上破壞訊號，然後設計更細的 guard 或 evidence-preserving loss。

可能設計：

1. 比較 base output、StageD output、StageE output。
2. 記錄 clean BA 與 attacked BA 的 per-image delta。
3. 找出 refiner 前正確、refiner 後錯誤的樣本。
4. 對這些樣本做 residual / frequency / bitplane 分析。
5. 設計 local guard、frequency-aware guard 或 decoder-gradient-aware refiner loss。

## 後續方向五：PSNR 往 36-37 dB 推進

| 項目 | 內容 |
|---|---|
| 目標 | 在 Clean BA >= 99、Avg BA >= 98、Min BA >= 90 的條件下提高 PSNR |
| 成本 | 高 |
| 風險 | 可能會再次犧牲 Dropout floor |
| 現階段建議 | 可作長期方向，但不建議現在推翻 StageE 主結果 |

代表意義：

DiffW-like 60k 顯示高 PSNR 是可能的，但 worst-case BA 弱。O256 若要往 36-37 dB 推，需要重新思考 VAE ceiling、refiner 架構、loss balance，可能不是單純加長 refiner 就能解決。

可能路線：

- VAE / decoder fine-tune。
- 更強的 image restoration refiner。
- perceptual loss / LPIPS-aware loss。
- frequency-preserving refiner。
- 分階段提高 PSNR，但每階段都用 full attack table 檢查 Min BA。

## 後續方向六：domain shift / 非 COCO 資料驗證

| 項目 | 內容 |
|---|---|
| 目的 | 確認 StageE 是否只在 COCO finaltest1000 上穩，或能推廣到其他資料 |
| 可能資料 | Kodak、DIV2K、BSDS、ABO renders、NaturalMix |
| 成本 | 中 |
| 風險 | 若結果不好，會開啟新的 domain adaptation 問題 |
| 現階段建議 | 可作補充驗證或後續研究 |

代表意義：

如果後續想把方法包裝成更實用的 watermark deployment protocol，domain shift 是很自然的下一步。但它不是目前主線結果成立的必要條件。

## 高成本實驗暫存規則

之後若討論到新的實驗，只要符合以下任一條件，就先記錄到本文件，不直接視為目前論文必做：

1. 需要完整 from-scratch base + refiner 重訓。
2. 需要 3 個以上 seed。
3. 需要大規模 sweep，例如多個 strength / S / loss weight。
4. 需要改模型架構或新增訓練模組。
5. 需要大量 per-image / per-bit / per-attack 診斷。
6. 結果主要是加強後續研究，而不是修補目前主結論。
