# O256 逐實驗實作方式與中文脈絡

## 1. 全中文脈絡段落

我的整個實驗脈絡是先從「比較基準」開始。`actual10k` 先做 1 萬張圖片的實際部署端速度測試，確認 O256 在大量產生浮水印圖片時確實比較快；`repeatability` 再做重複性檢查，確認這個速度不是單次剛好量到比較快。接著我回頭檢查 DiffW-like 這個對照方法本身的潛力，`diffw_epoch7` 看它實際多訓練幾輪後會不會自然變好，`diffw_60k` 則把訓練步數拉長到 60k，確認它可以拿到很高的 PSNR，但最弱攻擊下的位元準確率仍然偏低。之後我開始推 O256 自己的畫質和強健性取捨關係，`exp16` 先測基礎模型多訓練能不能推高 BA，`exp17` 發現 RGB 修復模組可以救畫質但可能犧牲 BA，`exp18` 到 `exp22` 逐步調整基礎模型和修復模組的訓練長度，確認 O256 畫質可以推到 34 dB 以上，但隨機遮蔽攻擊的最低表現會變成主要瓶頸。

接著，因為瓶頸開始集中在弱攻擊，我做了 `exp23` 弱攻擊基礎模型接續訓練，發現攻擊排程放在基礎模型訓練端比只改修復模組更關鍵；`exp24` 測弱攻擊導向的修復模組，確認只靠修復模組補強效果有限；`exp25` 開始從位元平面診斷哪些位元比較容易壞，`exp26` 用位元權重修復模組測試能不能針對弱位元補強，`exp27` 再把位元權重和弱攻擊放回基礎模型端，進一步確認真正有效的方向比較偏基礎模型訓練。接著 `exp28` 直接加重隨機遮蔽攻擊的訓練比例，第一次把最低 BA 明確推過 90%，但畫質下降；所以 `exp29` 到 `exp33` 都是在找怎麼把畫質救回來又盡量守住 BA，最後 `exp33` 形成第一個比較像正式候選的平衡點。

可是 `exp34` 重新驗證後發現 `exp33` 還不夠穩，`exp35` 和 `exp36` 的小幅修復模組補丁也補不上，所以我停損修復模組微調，改成基礎模型端的隨機遮蔽安全邊界。`exp37` 在 seed61 的接續訓練先通過，`exp38` 在 seed62 的接續訓練也通過，`exp39` 原本是鎖定條件驗證，但後來被完整重頭訓練取代。接著 `exp40` 是真正完整重頭訓練 seed61 並通過，成為目前主結果候選；`exp41` 再做 seed62，證明整體穩定，但隨機遮蔽最低 BA 只差 0.06 沒到 90。後面 `exp42` 測單純多加安全邊界，發現無法補上；`exp43` 開始診斷錯誤，發現問題比較像困難影像瓶頸；`exp44` 測困難樣本重播訓練，結果畫質升但隨機遮蔽更差；`exp45` 確認它沒有救回困難影像，反而新增失敗影像；`exp46` 進一步看到修復模組可能在抹掉浮水印證據；`exp47` 測加保護限制的第四階段修復模組，證明直接加殘差保護太粗，PSNR 會大幅崩掉，隨機遮蔽也沒有救回。接著 `exp48` 改成 bitplane 層級追蹤，確認目前正式 refiner 幾乎不傷 clean BA，真正問題是 Dropout 後的浮水印證據；`exp49` 再 audit 評估流程，排除 PSNR/BA 是因為配對錯誤或 message leakage 被灌高。確認方向與評估都站得住後，`exp50` 才回到模型側，用更強的 decoder-aware Dropout 訊息保護去補 refiner，結果 A/B 都把 seed62 Dropout floor 推過 90，其中 B 的畫質代價最小；`exp51` 再把 exp50B 固定成同一個 StageE 套到 seed61 和 seed62，確認 seed61 沒被破壞、seed62 也穩定過 90，所以這個 StageE 已經值得進入完整重頭訓練驗證；最後 `exp52` 把 StageE 寫進 seed62 完整 from-scratch protocol 從頭重跑，正式通過 PSNR、Clean BA、Avg BA、Min BA 門檻，證明 StageE 不是單純接續補丁，而是能成為正式流程的一部分。整條路線是從公平比較 DiffW-like，到建立 O256 的畫質/強健性取捨，再一路定位隨機遮蔽攻擊的最低表現，最後走到修復模組行為診斷與更結構化的訊息保留設計。

## 2. 每個實驗實際上怎麼做

| 代號 | 實際實作方式 |
|---|---|
| actual10k | 固定同一批 1 萬張圖片，分別跑 O256-Base、O256-RGB 和 DiffW-like 的端到端推論流程，量測每張圖平均需要多少時間。這個實驗不是看 BA 或 PSNR，而是直接看大量部署時誰比較快。 |
| repeatability | 重複執行推論速度量測，觀察每次測到的平均時間差異。因為變異很小，所以可以說 actual10k 的速度優勢不是一次性的偶然結果。 |
| diffw_epoch7 | 使用 DiffW-like 的實際訓練分支，把訓練從較短設定延長到 epoch 7，然後用同一套 finaltest1000、Clean BA、非幾何攻擊 BA 和 PSNR 評估。它的目的就是看 DiffW-like 多跑一點後是否自然補上弱點。 |
| diffw_60k | 把 DiffW-like 進一步拉到 epoch12 / 60k steps，再跑完整畫質與攻擊評估。這讓我們確認 DiffW-like 的畫質可以因長訓練明顯上升，但最弱攻擊下的 BA 仍然沒有一起被解決。 |
| exp16 | 從 O256 既有基礎模型接續訓練 +5k 和 +10k，評估 base 與 RGB 結果的 PSNR、Clean BA、非幾何攻擊 BA。這是在測「只靠多訓練基礎模型」能不能把 robustness 推上來。 |
| exp17 | 接在 exp16 的 +10k 結果後，額外訓練 RGB 修復模組，觀察 PSNR 是否回升以及 BA 是否受影響。結果讓我們看到 refiner 確實能修畫質，但也會吃掉一部分 BA。 |
| exp18 | 把基礎模型接續訓練延長到 +15k，再只做短的 refresh500 修復模組。這是在測能不能用較強 base 加較保守 refiner 取得比較平衡的點。 |
| exp19 | 沿用 +15k base，把 RGB refiner 從 refresh500 加到 refresh1000。這是在測多訓練 refiner 是否能提高畫質，以及 BA 會不會被壓下去。 |
| exp20 | 再把 +15k 的 refiner 加長到 refresh1500。這個實驗用來確認 refiner 長度和 PSNR/BA 的交換關係，結果顯示 PSNR 會上升但 BA floor 會繼續掉。 |
| exp21 | 改成 +20k base 搭配保守的 refresh500 refiner。它的做法是讓基礎模型先更穩，再用較短 refiner 修畫質，因此成為後面一段時間的平衡參考點。 |
| exp22 | 在 +20k base 上把 refiner 加長到 refresh1500。這是為了看 O256 畫質上限能不能往 34 dB 以上推，結果也讓我們看到 Dropout floor 會成為代價。 |
| exp23 | 從 +20k base 再多接續 5k，並把訓練攻擊設定改成 `identity_nongeom_targeted_weak` 這種弱攻擊導向排程；同時測 base 本身，以及把既有 +20k_refresh500 refiner 套上去後的 RGB 結果。因為只有 base 端訓練條件被換掉，refiner 是重用的，所以它可以分辨出改善主要來自 base-side attack schedule。 |
| exp24 | 固定前面的 base，改成訓練一個弱攻擊導向的 RGB refiner。這是對照 exp23：如果只改 refiner 也能補上 floor，代表 refiner-side 足夠；但結果有限，所以我們知道 base-side 比較關鍵。 |
| exp25 | 對既有候選結果做 per-bit / bitplane 診斷，計算不同 bit 在 clean 或 attack 後的 BA。它不是新訓練模型，而是把錯誤拆細，找出是不是某些 bit 特別容易壞。 |
| exp26 | 根據 bitplane 診斷產生 bit weight，訓練 bitweighted RGB refiner，讓比較弱的 bit 在 refiner 訓練中權重更高。結果顯示這對診斷有幫助，但不能只靠 refiner 解決最弱攻擊。 |
| exp27 | 把 bit weighting 和 weakattack 的想法放回 base-side，做基礎模型接續訓練。這是為了比較「弱 bit 補強」放在 base 端和 refiner 端哪個更有效，結果再次支持 base-side 更重要。 |
| exp28 | 從 A / exp23 類型的 checkpoint 出發，再多訓練約 5k steps，將攻擊 profile 改成 `identity_nongeom_dropout_focus`，也就是明顯增加 Dropout(0.3/0.2) 的抽樣比例，同時保留 GN、SP、JPEG、GF 避免過度只針對 Dropout。這讓 Min BA 第一次明確過 90%，但 PSNR 下滑。 |
| exp29 | 使用 exp28 的 base 產生 train pairs，訓練 refresh500 RGB refiner 來救畫質，再跑 finaltest1000 的畫質、Clean BA 和完整攻擊 BA。結果證明畫質可以救回一部分，但 Dropout floor 會掉破 90。 |
| exp30 | 改成更保守的 refresh250，減少 refiner 對 watermark evidence 的破壞。這個實驗確認短 refiner 比較能守 BA，但畫質提升有限。 |
| exp31 | 在 exp28 base 上訓練 message-preserving attack-aware refiner，讓 refiner 修圖時同時顧 clean message 和 attack 後 message。這是在測「修圖時也顧訊息」能不能比普通 refiner 穩，但結果還沒足夠。 |
| exp32 | 訓練更偏 Dropout-specific 的 refiner，把修復模組訓練重心放在 Dropout 下的訊息恢復。它讓 Dropout 很強，但 PSNR 代價過大，所以變成強 BA 但低畫質的極端點。 |
| exp33 | 把 exp32 的 Dropout 偏重調得比較平衡，做 dropout-balanced refresh500。這個實驗是想同時保留 exp28 的 BA 優勢和 refiner 的畫質修復能力，因此形成第一個比較像正式候選的平衡點。 |
| exp34 | 重新跑 exp33 候選路線的更嚴格驗證，包含重新產生 train pairs、重新訓練 refiner、再跑完整 finaltest1000 評估。這是為了確認 exp33 不是某次 reuse 或偶然結果，但結果顯示仍不夠穩。 |
| exp35 | 在 exp34 候選上做短的 Dropout compensation refresh150，嘗試用很小幅度的補償把 Min BA 推過 90。結果幾乎沒有補上，說明小補丁不足。 |
| exp36 | 改用 native dropout proxy 的 refiner refresh500，讓 refiner 訓練更貼近 Dropout 攻擊。結果仍未解決 floor，所以我們停止繼續在 refiner loss 微調上打轉。 |
| exp37 | 改回 base-side，從候選 checkpoint 接續 1 epoch，加入 dropout-margin 的 base 訓練設計。這是在測「把 Dropout 安全邊界放進 base」是否能比 refiner 補丁更有效，seed61 continuation 通過。 |
| exp38 | 用 seed62 重做 exp37 類型的 continuation validation。它的目的不是找新技巧，而是驗證 base-side dropout-margin 是否跨 seed 也有效；結果通過，所以值得升級成完整重頭訓練。 |
| exp39 | 原本規劃成 locked continuation validation，也就是把候選 protocol 條件鎖住再接續檢查。但後來 exp40 直接完整重頭訓練，因此 exp39 的主線必要性被取代。 |
| exp40 | 把探索出的正式候選 protocol 從零開始完整訓練 seed61：先 identity20k，再 nongeom light 到 base30 / base50，接著 weakattack +5k、dropout-focus +5k、dropout-margin +5k 到 base65；之後再做多階段 RGB refiner，包括 image、message、message plus、targeted、dropout-balanced StageD。這證明方法不是靠舊 checkpoint 接續才成立。 |
| exp41 | 用同一套 exp40 protocol 換 seed62 完整重頭訓練。它用來檢查正式候選流程跨 seed 是否穩定，結果整體指標穩定，但 Dropout Min BA 差 0.06。 |
| exp42 | 從 exp41 出發，額外測一段 dropout-floor safety margin，想看單純多加一點安全邊界能不能補上 seed62 的 0.06 gap。結果沒有補上，說明不能只靠多訓練一點解決。 |
| exp43 | 對 exp41 / exp42 的 Dropout error 做診斷，統計 hard images、per-image BA、hard set overlap 和 weak bit 分布。這讓我們看到問題比較像困難影像群，而不是固定某個 bit 永遠壞。 |
| exp44 | 根據 exp43 找出的 Dropout hardcase，建立 hardcase subset，拿來做 train-side hardcase replay，再跑完整評估。結果 PSNR 變高但 Dropout BA 更差，代表只重播困難樣本會把模型推向畫質修復而不是 robustness 修復。 |
| exp45 | 對 exp41 和 exp44 做逐圖 BA 差異分析，統計哪些影像被救回、哪些新掉到 90 以下、每張圖 BA 和 PSNR 的變化。結果發現 exp44 幾乎沒有救回原本 hard image，反而新增失敗圖。 |
| exp46 | 對 exp41 和 exp44 的輸出做 residual / frequency 診斷，包含殘差大小、Laplacian、高頻比例、refiner update 是否朝抵消 watermark residual 的方向走。結果支持 refiner 可能在追求畫質時抹掉部分 watermark evidence。 |
| exp47 | 根據 exp46 的假說，從 exp41 StageC 出發，只替換最後 StageD refiner，分成 mild guard 和 strong guard，加入 residual Laplacian preserve 與 anti-cancellation loss，再跑完整 finaltest1000 評估。結果 Clean BA 守住，但 PSNR 大跌且 Dropout 沒救回，說明這種直接加保護限制的方式太粗。 |
| exp48 | 不再訓練新模型，而是讀 exp40/41 的 base clean、base Dropout、RGB clean、RGB Dropout，以及 exp44/47 的失敗 refiner 對照，重新用 decoder 做 per-image / per-bit 統計。它比較 base 到 RGB、clean 到 Dropout、seed61 到 seed62、exp41 到 exp44/47 的 bit-level 變化，用來回答 weak bit 是否穩定，以及 refiner 到底是傷 clean 訊息還是傷 Dropout 後的浮水印證據。 |
| exp49 | 不改模型，而是 audit 評估流程。它用 stem-matched PSNR 重新檢查舊的 sorted-order PSNR 配對是否安全，並故意把 GT 圖片與 message 錯位做負控制；結果 stem 配對完全一致、wrong-GT PSNR 大幅下降、wrong-message BA 接近 50%，支持目前 PSNR/BA 評估沒有被配對漏洞撐高。 |
| exp50 | 固定 exp41 的 base，不重新訓練整顆模型，只針對 RGB 修復模組做 decoder-aware Dropout 補強。A 分支從 exp41 StageC 重新訓練最後 StageD，拉高 clean/message 與 Dropout attack-message 權重；B 分支則從 exp41 正式 StageD 做 250 steps 的低 learning-rate 小幅 refresh。兩條都跑同一套 finaltest1000、PSNR/SSIM/LPIPS、Clean BA 和完整非幾何攻擊 BA，用來測試 exp41 seed62 差 0.06 的 Dropout floor 是否能靠更直接的訊息保護補上。 |
| exp51 | 把 exp50B 的設定固定成候選 StageE，不再新增參數，分別接在 exp40 seed61 和 exp41 seed62 的正式 StageD 後面，各做 250 steps 低 learning-rate decoder-aware refresh。這個實驗是 cross-seed probe：seed61 用來確認 StageE 不會破壞原本已通過的結果，seed62 用來確認它能不能重現 exp50B 的 Dropout floor 修補。結果兩個 seed 都過 Min BA 90，且 PSNR 只小幅變動，因此下一步才有理由把 StageE 寫進完整 from-scratch protocol。 |
| exp52 | 把 exp51 驗證過的 StageE 寫進完整 seed62 protocol，從 base identity20k 開始重頭訓練，依序跑 nongeom-light、weakattack、dropout-focus、dropout-margin，到 base65 後重新產生 train10000 pairs，再從零訓練 RGB refiner StageA/B/B+/C/D，最後接上 StageE decoder-aware250，並用 StageE 輸出做 finaltest1000、Clean BA、完整非幾何攻擊 BA 和畫質評估。結果 PSNR 34.0379、Clean BA 99.99、Avg BA 98.76、Min/Dropout BA 90.33，正式證明 StageE 從頭訓練也成立。 |
